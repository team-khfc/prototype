디자인을 수정하고 팀에 전달하기

디자이너가 직접 수정할 수 있는 화면별 HTML·CSS 작업본입니다.

1. 설치 없이 시작하기

ZIP을 모두 압축 해제한 뒤 index.html을 Chrome 또는 Edge로 엽니다. ZIP 안에서 파일 하나만 열면 상대 경로의 스타일·폰트를 찾지 못할 수 있습니다.

Node.js·React·Docker·빌드 과정은 필요하지 않습니다. 포함된 화면은 디자인 검토용 합성 자료이며 실제 로그인·AI 분석·업무 저장·제출·기관 전송을 수행하지 않습니다.

2. 브라우저에서 문구와 토큰 수정하기

화면을 연 뒤 편집 도구의 ‘문구 편집 켜기’를 누릅니다. 편집 표시가 있는 문구를 클릭해 수정하고, 끝나면 ‘문구 편집 끄기’를 누릅니다. 입력칸의 예시 값도 직접 바꿀 수 있습니다.

‘디자인 토큰’에서는 제공된 색상·글자·간격 등의 조정값을 현재 화면에서 확인합니다. 한 화면의 변경안을 검토한 뒤 공통으로 반영할 값을 결정하세요.

레이아웃의 열 수·요소 순서·새 필드·새 컴포넌트는 HTML·CSS 소스를 수정합니다. 이 도구는 자유 드래그 방식의 레이아웃 편집기를 제공하지 않습니다.

브라우저의 변경은 원본 파일 자동 저장이 아닙니다.

작업을 마치거나 새로고침하기 전에 HTML 또는 변경본 백업을 내려받으세요. 원본 파일을 덮어쓰거나 서버에 저장하지 않습니다.

3. 목적에 맞게 내보내기

내보내기 기능과 파일 사용 방법
도구 담는 내용 사용 방법
HTML 내려받기 현재 문구·토큰·폼 값이 반영된 화면 HTML 원래 화면과 같은 상대 폴더 위치에 놓습니다. 공통 assets 폴더가 필요합니다.
변경본 백업 화면별 문구·입력값·토큰 변경의 JSON 같은 화면에서 ‘백업 불러오기’로 복원합니다. 모든 화면을 한 번에 담는 백업은 아닙니다.
토큰 CSS 내려받기 ‘디자인 토큰’에서 정한 변경값 검토 후 assets/css/design-overrides.css에 적용하여 여러 화면에 반영합니다.
단독 시안 CSS·폰트를 포함한 공유용 정적 HTML 파일 하나로 전달합니다. 편집 도구·화면 이동·업무 동작은 포함하지 않습니다.

내려받기 뒤에는 실제 파일을 다시 열어 반영 상태를 확인합니다. 운영 정보·실제 내부 IP·실존 개인정보·비밀값은 화면이나 백업에 입력하지 않습니다.

공통 토큰 파일을 바꾼 후에는 화면을 새로고침합니다. 화면별 편집본에 같은 토큰의 별도 변경값이 남아 있으면 공통값과 차이가 날 수 있으므로 인계 전에 비교해 주세요.

단독 시안은 내장 기본 CSS·글꼴과 현재 문구·입력값·지원 토큰을 담습니다. 외부 CSS 파일을 직접 수정한 레이아웃이나 새 CSS 규칙은 자동으로 묶지 않습니다. 이러한 변경은 HTML과 assets 폴더를 함께 전달해 주세요.

4. 직접 수정할 파일 찾기

변경 목적별 파일
바꾸고 싶은 것 작업 위치
화면 문구·항목·배치·읽기 순서 해당 화면의 HTML
팀이 합의한 공통 토큰 변경 assets/css/design-overrides.css
추가된 화면 보완 스타일 assets/css/screen-patches.css
기본 원본 스타일·토큰 확인 assets/css/tokens.css, styles.css, workspace.css, handoff.css

공통 헤더·메뉴는 각 HTML에 포함되어 있습니다. 원본 CSS는 보존하고 변경값은 별도 CSS에 추가합니다. 헤더·메뉴의 마크업을 바꾸면 영향을 받는 화면에도 같은 변경을 적용해야 합니다.

5. 새 화면 만들기

새 화면 템플릿을 같은 templates 폴더에 다른 이름으로 복제합니다. 예를 들어 request-detail.html처럼 영문 파일명을 사용합니다.

복제한 파일의 문서 제목 title, 페이지 제목 h1, 본문 내용, body의 data-screen을 수정합니다. 예시 식별자는 templates/request-detail.html입니다. 파일마다 식별자가 달라야 화면별 백업이 섞이지 않습니다.

같은 폴더에 복제하면 data-base="../"와 공통 자산 경로를 유지할 수 있습니다. 다른 깊이의 폴더로 옮기면 링크·CSS·스크립트의 상대 경로도 조정해야 합니다.

컴포넌트는 기존 화면 또는 컴포넌트 가이드에서 가져옵니다. 새 입력을 추가하면 고유한 id, 연결된 label, 도움말·오류 설명을 함께 만듭니다.

마지막으로 화면 목록에서 찾을 수 있도록 루트 index.html의 목록에 새 화면 링크를 추가하고 역할·목적·주요 상태를 기록합니다.

6. 검토할 화면과 상태

기본 PC 프레임은 1920×1080입니다. 1440px·768px·360px 너비와 브라우저 확대에서도 문구·버튼·표를 확인합니다. 화면 높이를 1080px로 고정하거나 페이지 전체에 가로 스크롤을 만들지 않습니다.

7. 개발자에게 전달하기

변경한 HTML, 공통 토큰 CSS, 필요한 추가 CSS, 화면별 변경본 백업을 같은 패키지로 전달합니다. 빠른 검토가 필요하면 단독 시안을 함께 보냅니다.

8. Figma에서 재구성할 때

이 산출물은 HTML 작업본입니다. 네이티브 Figma 파일(.fig) 생성이나 Figma 자동 동기화는 제공하지 않습니다. HTML 수정이 기존 Figma 파일을 자동으로 바꾸지도 않습니다.

Figma에서 작업하려면 Foundations / Components / Patterns / Screens 페이지를 만들고 이 패키지를 기준으로 프레임과 컴포넌트를 재구성합니다.

HTML과 Figma 작업의 대응
HTML 기준 Figma에서 정리할 것
Foundations 의미별 색상 변수, Pretendard GOV 400/700 사용 가능 여부, 텍스트 스타일·행간·간격
Components Button / Field / StatusBadge / Panel / DataTable / Dialog 등 재사용 컴포넌트
Patterns 기본·초점·비활성·로딩·오류·선택 상태와 복구 행동
Screens 1920×1080 기본 프레임과 작은 화면의 배치, Auto Layout, 최소/최대 너비·줄바꿈

예를 들어 --sf-primary를 Color/Primary, 본문 17px·행간 150%를 Text/Body처럼 대응시킵니다. 이름은 팀이 합의한 체계로 통일하고 HTML 토큰 이름과의 대응을 남깁니다.

컴포넌트의 모양뿐 아니라 상태·초점·스크롤·버튼 동작 조건을 함께 인계합니다. 외부 가져오기 플러그인의 호환성을 검증한 것으로 표시하지 않습니다.
