# 보안길잡이 디자이너 작업본

2026-11-06 · HTML / CSS / JavaScript · 합성 데이터

디자이너가 보안길잡이의 화면을 만들고 수정하여 개발자에게 전달하는 작업 패키지다. 지정 디자인 시안의 업무 화면 15개와 공통 컴포넌트 가이드를 바탕으로, 브라우저 문구 편집·토큰 조정·파일 내보내기를 추가했다.

## 처음 열기

1. ZIP 파일의 **압축을 모두 푼다**. 압축 파일 안에서 HTML만 바로 열면 연결된 글꼴·CSS를 찾지 못할 수 있다.
2. 폴더 안의 **`index.html`을 Chrome 또는 Edge로 연다**.
3. 화면 목록에서 수정할 화면을 선택한다. 화면별 HTML을 직접 열어도 된다.
4. 상단의 **문구 편집 켜기**를 누르고 표시된 문구를 수정한다. 입력칸·선택값은 해당 컨트롤에서 변경한다.
5. **HTML 내려받기**로 편집본을 남긴다. 브라우저는 원본 파일을 자동으로 덮어쓰지 않는다.

Node.js·Java·Docker 설치와 로그인은 필요하지 않다. 실행 중 외부 폰트·CDN·업무 API를 사용하지 않는다. 사용하는 브라우저의 로컬 파일 정책으로 차단된다면 VS Code의 로컬 미리보기 등 허용된 정적 파일 서버에서 같은 폴더를 연다.

HTML 작업 가이드: [docs/DESIGN_GUIDE.html](docs/DESIGN_GUIDE.html).

## 수정과 내보내기

### 문구·입력 내용 수정

문구 편집 모드를 켜면 편집할 수 있는 텍스트를 구분해 보여 준다. 붙여넣은 내용은 평문으로 처리한다. 메뉴 링크를 탐색하려면 편집 모드를 끈다. 표의 검색 결과 수처럼 자동 갱신하는 문구와 도구 자체의 문구는 편집 대상에서 제외한다.

폼의 현재 입력값·선택값·체크 상태는 HTML 내보내기에 반영된다. 파일 선택 컨트롤의 실제 파일 내용·비밀번호는 편집본에 보존하지 않는다. 실제 개인정보·내부망 정보·비공개 자료를 입력하지 않는다.

### 디자인 토큰 조정

**디자인 토큰**에서 색상·반경 등 제공되는 값을 조정하면 현재 화면에 적용된다. 참고용 대비 계산은 표시되는 색상 조합만 다루며 전체 화면의 접근성 검사를 대신하지 않는다.

**토큰 CSS 내려받기**로 받은 `design-overrides.css`를 패키지의 `assets/css/design-overrides.css`와 교체하면 공통 값을 모든 화면에 적용할 수 있다. 각 페이지를 새로고침하여 확인한다. 개별 편집본 HTML에 이미 내장된 토큰 변경이 있으면 해당 화면의 값이 우선하므로, 공통 적용 전 개별 변경과 비교한다.

KRDS 공급 토큰과 원본 CSS는 보존한다. 색상·간격 변경을 기관별 업무 권한이나 제출 조건 변경으로 해석하지 않는다.

### 내보내기 종류

| 내보내기          | 용도                               | 다시 사용할 때                                                              |
| ----------------- | ---------------------------------- | --------------------------------------------------------------------------- |
| HTML 내려받기     | 계속 수정할 화면 작업본            | 원래 화면과 같은 상대 위치에 두고 `assets/` 폴더와 함께 사용                |
| 단독 시안         | 다른 사람이 확인할 정적 HTML       | CSS·글꼴이 내장되어 한 파일로 전달 가능. 편집 도구·화면 이동·업무 동작 제외 |
| 토큰 CSS 내려받기 | 공통 스타일 변경 전달              | `assets/css/design-overrides.css`에 반영                                    |
| 변경본 백업       | 현재 화면의 문구·폼·토큰 변경 보관 | 같은 화면에서 백업 불러오기로 복원                                          |

다운로드 폴더에 이미 같은 이름의 파일이 있으면 브라우저가 이름 뒤에 번호를 붙일 수 있다. 원래 파일을 보관한 뒤 의도한 파일명을 확인하여 교체한다. 다른 화면의 JSON이나 임의 HTML을 백업 불러오기에 넣지 않는다.

단독 시안은 패키지에 내장한 기본 CSS·글꼴과 현재 화면의 문구·입력값·지원 토큰을 담는다. 외부 CSS 파일을 직접 수정한 레이아웃이나 새 CSS 규칙은 자동으로 묶지 않으므로, 그런 변경은 HTML과 `assets/`를 포함한 전체 폴더로 전달한다.

브라우저에서 편집한 내용은 페이지를 닫으면 사라질 수 있으므로 **이동하거나 닫기 전에 편집본 또는 JSON 백업을 내려받는다.** 자동 클라우드 저장·공동 동시 편집은 제공하지 않는다.

## 새 화면 만들기

`templates/blank-screen.html`을 복사하여 같은 `templates/` 폴더에서 새 이름으로 저장한다. 다음을 HTML 편집기에서 바꾼다.

- `<title>`, 본문 `h1`, 현재 메뉴와 설명
- `body`의 `data-screen`을 새 상대 파일 경로로 변경
- 패널·입력·표의 구성과 내용, 중복되지 않는 `id`와 `label for`

다른 폴더로 옮겼다면 CSS·스크립트·메뉴의 상대 경로와 `data-base`를 함께 조정한다. 레이아웃을 자유롭게 끌어 놓는 빌더는 포함하지 않았다. 구조 변경은 HTML/CSS로 하고 문구·토큰 조정은 브라우저 도구로 할 수 있다.

## Figma로 정리할 때

이 결과물의 원본 형식은 **HTML**이다. 네이티브 `.fig` 파일이나 Figma 자동 동기화를 제공하는 것은 아니다.

Figma에서 재구성할 때는 `Foundations / Components / Patterns / Screens`로 페이지를 나누고, `SCREEN_INDEX.csv`의 화면 ID와 `TOKEN_MAPPING.csv`의 이름을 사용한다. 업무 기준 프레임은 1920×1080이며 작은 화면·확대 상태를 별도로 확인한다. HTML을 가져오는 도구의 레이어·Auto Layout·컴포넌트 변환 결과는 별도 검토가 필요하다. 특정 가져오기 플러그인의 호환성을 검증했다고 표시하지 않는다.

## 업무와 시안의 구분

두 문서 종류(방화벽·보안성검토), 네 역할(일반 사용자·정보보안·ICT인프라·기관 관리자)을 유지한다. AI 제안과 사람이 확인한 값, 설정 초안과 게시본, 문서 초안과 제출본, 담당자 검토와 실제 처리를 구분한다.

화면의 저장·분석·검토·제출·게시 버튼은 **디자인 상태와 다음 화면을 검토하는 예시**다. 실제 업무 저장, AI 호출, 기관 전송, 권한 검증을 수행하지 않는다. 디자인 결과를 서비스에 반영할 때는 개발자가 React 공통 컴포넌트와 서버 계약을 확인한다.
