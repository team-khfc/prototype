상태 예시 · 확인 필요

원출처와 사람이 확인했는지를 별도로 보여 줍니다. 제안이 존재한다는 이유만으로 확인 완료가 되지 않습니다.

02. AI 분석 실패

상태 예시 · 분석 실패
사업개요서 분석을 완료하지 못했습니다.

입력한 사업 설명은 유지됩니다. 다시 분석하거나 직접 답변을 작성해 주세요.

실패 상태를 고정 예시 결과나 성공 메시지로 대체하지 않습니다. 기술 오류 원문 대신 사용자 행동과 문의용 번호를 안내합니다.

03. 입력이 바뀐 뒤 도착한 분석 결과

상태 예시 · 이전 입력 기준
현재 입력과 분석 기준이 다릅니다.

이 결과는 수정본 4를 기준으로 생성한 예시입니다. 현재 사업 설명은 수정본 5입니다. 최신 답변에 자동으로 덮어쓰지 않습니다.

기준이 달라 제안 적용을 막는 상태입니다. 이전 근거를 확인하거나 최신 입력으로 다시 분석할 수 있게 설계합니다.

04. 권한 제한

상태 예시 · 접근 제한
이 신청의 내용을 볼 권한이 없습니다.

접근할 수 있는 업무 목록에서 신청을 확인해 주세요. 도움이 필요하면 기관 관리자에게 문의해 주세요.

허용되지 않은 신청의 제목·작성자·첨부 내용을 오류 안내에 포함하지 않습니다. 화면의 역할 선택은 서버 권한을 대신하지 않습니다.

05. 다른 담당자의 수정과 충돌

상태 예시 · 버전 충돌
저장된 내용이 바뀌었습니다.

현재 편집 내용을 유지했습니다. 최신 저장값과 비교한 뒤 다시 적용할 내용을 선택해 주세요.

다시 불러오기로 무엇이 바뀌는지 설명하고 미저장 입력을 조용히 버리지 않습니다.

06. 세션 만료와 복구

상태 예시 · 로그인 필요
로그인 시간이 만료되었습니다.

다시 로그인하면 마지막으로 저장한 초안부터 이어서 작성할 수 있습니다. 저장되지 않은 변경은 복구 가능 여부를 확인해야 합니다.

만료 전 안내에는 남은 시간·‘로그인 연장’·‘로그아웃’을 제공합니다. 프로젝트 기본 설계는 60초 전 안내이며, 실제 연장은 서버 성공 응답에 따라 표시해야 합니다.

이 카드에는 실제 타이머나 로그인 기능이 없습니다. 비밀번호·토큰을 디자인 백업에 입력하지 않습니다.

07. 초안·게시본·제출본

상태 예시 · 대상별 버전

기관 설정의 버전과 신청 문서의 버전을 분리해서 표시합니다.

대상에 따른 초안 게시본 제출본 구분 예시
대상·상태 예시 버전 사용자에게 설명할 의미
기관 설정 · 수정 초안 게시본 v2에서 편집 중 초안 저장만으로 새 신청에 적용되지 않습니다.
기관 설정 · 게시본 게시본 v2 이 버전으로 생성한 신청은 이후 게시에도 설정을 유지합니다.
신청 문서 · 제출본 제출본 v1 / 기관 설정 v2 제출 당시 내용을 보존합니다. 현재 편집 중인 초안과 구분합니다.

설정 게시와 신청 제출은 다른 행동입니다. 제출본을 열어 보았다는 이유로 검토·접수·실제 처리를 완료하지 않습니다.

상태 예시 · 제출 준비

완료된 검토와 제출할 내용을 확인한 뒤 최종 행동을 구분합니다.

제출 후에는 제출 당시 문서와 설정 버전을 확인할 수 있습니다. 제출이 실제 방화벽 적용 완료를 뜻하지는 않습니다.

실제 서비스에서는 서버가 필수값·미확정·보완·검토 버전을 다시 검사하고, 성공 응답을 받은 뒤 완료 화면을 보여 줍니다.

09. 빈 목록과 검색 결과 없음

상태 예시 · 다음 행동

아직 작성한 신청이 없습니다.

사업을 설명하면 필요한 정보를 차근차근 정리할 수 있습니다.

조건에 맞는 신청이 없습니다.

검색어 또는 선택한 상태를 바꾸어 다시 확인해 주세요.

처음부터 데이터가 없는 상태와 현재 검색 조건에 결과가 없는 상태를 구분합니다. 조회 실패를 ‘0건’으로 표시하지 않습니다.
