# 개발 시작점 확인 시나리오

작성일: 2026-11-07. FUNCTIONAL_SPEC v1.7의 필수 경로와 불변식을 팀원이 재현할 때 사용한다. **아래 표는 실행 절차와 기대 결과다. 통과 기록이 아니다.** 실제 실행 환경·결과는 [verification-starter.md](verification-starter.md)에 따로 기록한다.

## 준비와 입력 자료

공개 `/starter`에서는 화면 흐름을 설명하고, 실제 검증은 로그인 후 `/business-cases`와 `/security-requests`에서 수행한다. 같은 시나리오라도 두 경로의 결과를 합치지 않는다. 저장소 밖의 기관 자료·개인정보는 사용하지 않는다.

| 항목 | 합성 입력 예시 |
|---|---|
| 사업명 | 가상 공개자료 안내 서비스 |
| 부서 | 시연 기획팀 |
| 사업 설명 | 공개된 행사 안내를 검색하는 합성 서비스. 실제 기관 시스템과 연결하지 않음 |
| 처리 정보 | 합성 행사명·공개 안내 문구, 실제 개인정보 없음 |
| 외부 전송 | 시연 설정에 맞는 허용 선택값과 설명. 모르면 확인 필요로 남김 |
| 통신 정보 | 가상 출발 시스템 → 가상 도착 시스템, 문서용 주소 `192.0.2.10` → `198.51.100.20`, TCP 443 |
| 방화벽 신청 목적 | 합성 안내 API의 HTTPS 통신 검토 |
| 보안성검토 범위 | 합성 서비스의 접근통제·로그·자료 흐름 검토 |
| 반환 사유 | 공개자료와 합성자료의 범위를 구체적으로 구분해 주세요 |

문서용 주소는 형식 설명용이다. 실제 장비 적용이나 기관 통신 사실로 해석하지 않는다. 필드의 허용값은 서버가 제공하는 질문과 API 계약을 따른다.

## A. 정상 경로와 반환 1회

| 순서 | 실제 계정·행동 | 기대 결과 |
|---|---|---|
| 1 | `/signup`에서 합성 계정을 만든 뒤 로그인하거나 `applicant.demo` 로그인 | 로그인 시 서버 세션 생성. 신규 가입은 APPLICANT이며 가입만으로 자동 로그인하지 않음 |
| 2 | 사업 건을 생성하며 FIREWALL·SECURITY_REVIEW 두 유형 선택 | BusinessCase 1개와 서로 다른 SecurityRequest 2개. 중복 유형은 거부 |
| 3 | 공통 설명 입력 또는 TXT/MD를 선택한 뒤 명시적으로 분석 요청 | 선택만으로 전송하지 않음. 기본 EXAMPLE은 원문 추출로 표시 |
| 4 | AI 후보의 근거를 읽고 확인 가능한 공통 값을 사람이 확인 | `AI_INFERRED` 원출처와 확인 기록 구분. 근거 없는 값은 확정 사실로 표시하지 않음 |
| 5 | 공통 질문 1회와 각 서류 질문 작성 후 한 신청에서 협의 요청 | 해당 신청만 2단계. 자동 배정·협의 기한 생성. 다른 신청은 그대로 |
| 6 | `infra.demo`로 공통 통신 항목 입력·확인 후 해당 신청의 할당 완료 | INFRA 할당 완료 표시. INFRA 검토 완료로 자동 처리하지 않음 |
| 7 | `security.demo`로 보완할 필드와 사유를 지정하고 보완·반환 흐름 수행 | 보완 요청 이력, 2→1 반환 사유, 지정 필드 강조. 기존 값·할당·이력 보존 |
| 8 | 신청자가 강조 필드와 보완 답변을 수정하고 다시 협의 요청 | 새로운 차수의 기한·재검토가 생기고 이전 기록 보존 |
| 9 | 필요한 할당·보완 해결과 INFRA·SECURITY 협의 완료 | 두 분야 검토가 완료될 때만 3단계 사용자 최종 검토 |
| 10 | 신청자가 필수값·미확정 AI·미해결 보완을 확인한 뒤 제출 | 서버가 조건을 재검사. 4단계 SUBMITTED와 불변 제출본 생성 |
| 11 | `infra.demo` 최종 확인 → `security.demo` 최종 확인 | 같은 제출본에 대한 두 확인. 확인 순서 유지 |
| 12 | 배정된 `security.demo`가 확정 | FINALIZED. 방화벽 실제 적용 완료로 표시하지 않음 |
| 13 | 문서 다운로드·처리 이력 확인 | 제출 시점 값 보존, 감사의 행위·주체·대상·버전 확인 가능 |
| 14 | 남은 서류를 조회·진행 | 앞선 신청의 확정이 다른 신청을 자동 확정하지 않음 |

“AI 최종 초안”은 사람이 확인하기 전 미확정이다. 현재 UI·API에 연결되지 않은 자동 작성 부분을 대본만으로 완료 처리하지 않는다. 새 API 동작과 질문 키는 [starter-api.md](starter-api.md)에 따른다.

## B. 상태·권한·데이터 거부 경로

각 항목은 새 합성 사업 건이나 이미 종료되지 않은 신청에서 재현한다. 거부된 요청 뒤에는 상태·revision·감사가 어떻게 남았는지도 확인한다.

| 확인할 상황 | 기대 결과 |
|---|---|
| 두 탭에서 같은 revision 조회 후 한 탭 저장, 다른 탭 저장 | 409와 최신 revision 안내. 미저장 입력 보존 |
| 공통 답변 API에 신청 revision 사용 | 공통 정보는 caseRevision을 사용. 오래된 공통 버전은 거부 |
| INFRA 할당 전 SECURITY 협의 완료 | 거부. 단순 조회와 완료 권한을 구별 |
| 할당 완료만으로 신청자 제출 | INFRA·SECURITY 협의 완료가 없으면 거부 |
| 미확정 AI 후보·필수값 누락·미해결 보완이 있는 제출 | 거부. HTTP 200 성공으로 숨기지 않음 |
| 동일 Idempotency-Key로 같은 제출 재전송 | 제출본이 중복 생성되지 않음. 다른 요청 재사용의 거부도 확인 |
| 같은 제출본의 두 최종 확인 없이 확정 | 거부. ADMIN·신청자·비배정 담당자의 확정도 거부 |
| 2→1·3→2·3→1·4→3 외 반환 또는 사유 없는 반환 | 거부. 유효한 반환은 기존 값·제출 이력을 보존 |
| 제출 후 공통 정보 변경 | 다른 미제출 신청만 영향 재검토. 기존 제출본의 공통 값 불변 |
| 종결·철회·확정 후 수정·분석·재반환 | 거부. 조회·다운로드만 허용 |
| `second.demo` 또는 `outside.demo`가 타인 신청 ID로 조회·수정·다운로드 | 서버에서 작성자·기관 권한 검사. 존재 여부와 민감 본문을 불필요하게 노출하지 않음 |
| 검토 역할이지만 해당 신청에 배정되지 않은 담당자의 명령 | 403. 화면 버튼 노출 여부와 별개로 거부 |
| 관리자 재배정 시 사유 누락·신청자 본인 지정·다른 기관 계정 지정 | 거부. 정상 재배정은 이전 배정을 비활성 보존 |
| 회원가입 요청에 ADMIN 역할·다른 기관 값을 추가 | APPLICANT·합성 시연 기관으로만 생성. 클라이언트 값으로 승격하지 않음 |
| CSRF 토큰 없이 변경 요청 또는 세션 만료 후 명령 | 인증/CSRF 경계에서 거부. 성공 메시지 표시 금지 |
| 감사 저장 실패와 업무 변경 실패 | 동일 트랜잭션으로 일관되게 롤백. 감사 수정·삭제 API 없음 |
| 주말·기관 공휴일을 포함한 기한, 반환에 따른 재계산 | 영업일 계산, 기존 기한 종료·새 기록, 기한 경과만으로 상태 불변 |

권한 확인을 위해 실제 사람의 계정이나 기관 자료를 만들지 않는다. 계정·배정 변형이 필요하면 테스트 fixture 또는 로컬 합성 시연 관리자 기능을 사용한다.

## C. AI와 업로드 연결 인수

| 경로 | 기대 결과와 증거 |
|---|---|
| 키 없는 EXAMPLE 분석 | 실제 외부 LLM을 호출한 것처럼 표시하지 않음. 근거·미확정 후보만 제안 |
| TXT/MD 및 파일 크기 제한 | 현재 최대 1 MiB 입력 범위를 확인. PDF/DOCX/HWP를 지원하는 것처럼 표시하지 않음 |
| AI 처리 도중 사업 건 내용 변경 | 대상 revision을 확인해 오래된 후보가 최신 답변을 덮지 않음 |
| 확인 완료 값에 새 AI 후보 적용 | 사람 확인을 조용히 덮어쓰지 않음 |
| 모델 오류·키 없음·허용되지 않은 엔드포인트 | 실패와 재시도를 설명. 예시 성공으로 대체하지 않음 |
| 기관 비공개 컨텍스트·악성 업로드 지시문 | 컨텍스트를 임의로 외부 전송하지 않음. 문서 속 명령은 데이터로 취급 |
| 실제 모델 2종 교체 | 같은 합성 입력에서 실행한 제공자·모델·대상 revision·결과·한계를 기록. 키와 민감 프롬프트 원문은 기록하지 않음 |

Spring AI·PGVector 의존성 추가, EXAMPLE 실행, 외부 모델의 프로토콜 단위 테스트만으로 실제 모델 2종 구동이나 RAG 색인·검색을 입증하지 않는다.

## D. 시연에 포함하지 않는 완료 주장

F-15 정책 수명주기, F-16 업무 지표, F-17 화면 안 알림은 **설계 완료·구현 예정**이다. 방화벽 장비 적용, SSO, 부서장 확인, 외부 메신저·메일 알림은 이번 완료 경로가 아니다. 관련 테이블이나 예정 안내 화면은 구현 완료 증거로 쓰지 않는다.

인수자는 재현한 시나리오 ID·사용 경로·환경·합성 데이터 초기화 여부·결과·미검증을 PR에 남긴다. 이전 2026-11-06 결과를 이번 변경의 통과로 복사하지 않는다.
