# ADR 0002 — 서버 업무 전이와 값의 출처

- 상태: 이번 프로토타입에 적용
- 일자: 2026-11-06

## 결정

- 신청자, 정보보안, ICT인프라, 기관 관리자 네 역할을 DB 계정으로 관리한다. 세션의 계정 상태와 역할도 요청마다 DB에서 다시 확인한다.
- 신청자는 본인 신청만 접근한다. 전문 담당자의 접근은 기관 범위와 협의 단계에 제한한다. 기관 설정 권한은 신청 내용의 열람 권한을 자동으로 포함하지 않는다.
- `expectedRevision`은 화면이 편집한 업무 버전이다. JPA의 저장 버전과 분리하여 충돌을 판단하고, 비관적 행 잠금으로 복수 담당자의 전이를 직렬화한다.
- 값의 원래 출처와 이후 사람의 확인을 별도 필드에 저장한다. AI 제안을 사람이 확인해도 AI였다는 원래 출처·근거를 지우지 않는다.
- `EMPTY`, `PROPOSED`, `CONFIRMED`, `NOT_APPLICABLE`을 구별한다. 모르는 값은 해당 없음으로 자동 처리하지 않는다.
- 보완과 중요한 변경은 완료 검토의 유효성을 다시 판단한다. 순차·병렬 검토는 신청 생성 때 고정한 기관 정책을 따른다.
- 최종 제출 때 필수값, 미확정 후보, 미해결 보완, 담당자 검토를 서버에서 검사한다. 제출 명령은 멱등성을 보장하고 제출 당시 자료를 별도 스냅샷으로 보존한다.
- 제출 스냅샷은 애플리케이션과 DB 트리거에서 수정·삭제를 거절한다. 접수는 별도의 업무 전이이며 실제 방화벽 장비 적용으로 표시하지 않는다.
- 기관 정책은 편집 초안과 게시 버전을 구별한다. 새 게시본은 새 신청에 적용하고 기존 신청의 질문·검토 절차를 소급 변경하지 않는다.

## 한계와 운영 이관

현재 로그인과 요청 제한은 단일 서버 시연 범위다. 운영 SSO·계정 수명주기·분산 세션·분산 요청 제한·중앙 감사 저장은 별도 통합이 필요하다. 정적 파일 화면만으로 서버의 업무 검증을 대신하지 않는다.
