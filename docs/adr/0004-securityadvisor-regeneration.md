# ADR 0004 — 최신 명세·디자인에 맞춘 SecurityAdvisor 재생성

- 일자: 2026-11-06
- 상태: 요청된 프로토타입에 적용, 팀의 main 병합 승인과 구별
- 근거: 프로젝트 지침 v1.4, PROJECT_CONTEXT v1.9, FUNCTIONAL_SPEC v1.2, AGENTS v1.5, 디자인 커밋 07c2b598
- 대체: ADR 0001·0002의 스택·작업 저장소·검토 순서 결정

## 결정과 이유

서비스명 SecurityAdvisor, Java 루트 `kr.securityadvisor`, 프론트 `features/<context>`, API `/api/security-requests`를 사용한다. Java 25 LTS·Spring Boot 4.1·Spring AI 2.0 고정 요구를 반영하고 Java 25 실행을 지원하는 Gradle 9.1.0과 포맷터를 사용한다. 이전 문서의 Java 21과 SECURITY 선행 절차는 최신 확정 명세로 대체한다.

처리 절차는 작성→담당자 협의→사용자 최종 검토→확정·관리의 4단계다. 자원 할당은 INFRA 협의 완료와 다른 상태이며 SECURITY 검토의 선행 조건이다. 두 협의가 완료되어야 3단계로 진행하고, 두 최종 검토 후 서류를 확정한다. 최종 AI 보완분은 사람이 확인하기 전까지 미확정이다.

차수 반환은 허용된 네 경로와 사유·대상 항목을 도메인에서 검사한다. 값·할당·이력을 지우지 않고 선택 항목과 영향받는 확인에 재검토를 요구한다. 종결·철회는 사유를 보존하고 이후 변경을 막는다. 제출본은 개정별 불변 스냅샷이며 이전 제출본의 조회·다운로드를 유지한다.

신청 애그리거트가 업무 생애주기를 관리하고, review의 순수 도메인 서비스가 검토 결정을 제공한다. document는 불변 제출본과 렌더링을 맡는다. 컨텍스트 사이에는 공개 서비스·불변 DTO·ID만 교환하며 다른 컨텍스트의 엔티티·저장소에 직접 접근하지 않는다. 실용적인 전술 DDD만 적용하고 이벤트 소싱·CQRS는 도입하지 않는다.

## 기존 자료 보존

main에 이미 있는 Flyway 세 파일은 수정하지 않는다. 새 마이그레이션으로 출처·업무 상태·차수 제출·LLM 설정·vector 확장을 이관한다. `procedures` 등 기존 테이블·DB명·계정·업로드 경로는 호환성을 위해 유지한다. 프로젝트 표시 이름을 바꾸더라도 기본 Compose 볼륨 이름은 기존 `security-advisor-design_*`를 계속 참조한다. 새 볼륨은 환경변수로 명시적으로 선택할 수 있다.

환경변수의 표준 이름은 `SECURITYADVISOR_*`이며 기존 `BOAN_*`는 이관용 fallback이다. 초기화 스크립트는 비밀값을 재생성하지 않고 기존 값에 새 별칭만 추가한다. 세션 쿠키는 SecurityAdvisor 이름으로 바꾸므로 기존 로그인은 다시 해야 한다.

## 디자인·저장소

참조 HTML·CSS·로고·토큰·글꼴은 원본 디렉터리에 보존한다. 최신 10개 업무 화면에 대응하는 React 컴포넌트를 구현하며 정적 시안의 고정 성공·역할 선택을 인증이나 저장으로 사용하지 않는다. `prototype`의 검토 브랜치에 재생성본을 제공하고 본 저장소 통합은 PR 검토 후 별도로 수행한다.

공개 DNS 등록 없이 로컬 주소 `securityadvisor.localhost:3000`, `api.securityadvisor.localhost:8080`와 Docker 별칭을 사용한다. 브라우저는 같은 출처 `/api` 프록시로 통신한다.

## 축소 구현과 검증

전문 담당자 권한은 기관·역할 단위이며 개별 배정 기능은 후속 범위다. 업로드 TXT·MD, 출력 HTML, 공개자료 요약 색인, 운영 인증 대신 시연 세션의 한계를 화면과 README에 명시한다. 실제 수행한 검증만 VERIFICATION.md에 기록한다.
