# ADR 0004 — 기존 자산을 보존한 팀 개발 시작점

- 일자: 2026-11-07
- 상태: 이번 시작점에 적용한 구현 결정. 팀의 PR 승인·병합 완료를 의미하지 않음
- 대상: `team-khfc/prototype`의 기능 브랜치
- 기준: PROJECT_CONTEXT v2.7, FUNCTIONAL_SPEC v1.7, AGENTS v1.10, 사용자의 팀 개발 시작점 구현 요청

## 배경

기존 저장소에는 세션 인증, PostgreSQL·Flyway, procedure 업무 예제, 분석 어댑터, 기관 설정, Next.js 화면과 테스트가 있다. 최신 규칙은 사업 건 1:N 신청, INFRA 할당·검토 분리, 신청별 반환·제출·확정, 배정·기한·감사를 요구한다. 기존 예제를 전부 대체하면 이미 확인한 인증·저장·안전 전송 자산을 잃고, 그대로 새 기준이라고 설명하면 업무 의미가 달라진다.

이번 사용자 요청은 이 저장소를 각 팀원의 개발 시작점으로 만드는 것이다. ADR 0001의 “prototype 보관 저장소에 새 개발 코드를 쓰지 않는다”는 당시 결정은 이번 작업 범위에 적용하지 않는다. 이전 ADR와 검증 이력은 삭제하지 않는다.

## 결정

1. **기존 경로와 새 업무를 병행한다.** 기존 procedure/analysis/institution API와 이전 migration을 보존한다. 신규 `/api/business-cases`, `/api/security-requests`는 별도 1:N 업무 모델로 구현한다. 두 모델의 레코드는 자동 복사·동기화하지 않는다. 새 프런트엔드는 새 자원을 사용한다.
2. **공통 인증과 런타임을 통일한다.** Java 패키지는 `kr.securityadvisor`, toolchain은 Java 25를 사용한다. Gradle wrapper는 9.1.0으로 고정한다. 기존 `BOAN_*` 환경변수와 DB 연결 이름은 실행 호환성을 위해 유지한다. 새 회원가입은 합성 시연 기관의 APPLICANT만 생성한다.
3. **공개 시연과 실제 업무를 분리한다.** `/starter`는 메모리 합성 시연이며 역할별 보기가 인증을 뜻하지 않는다. `/business-cases`와 `/security-requests`는 실제 세션·CSRF·DB와 서버 권한을 사용한다. 기존 `/design-preview`는 공개 읽기 전용 표시 예제로 유지한다.
4. **업무 불변식을 domain에 둔다.** 단계와 상태, 반환의 값 보존, 필수값·미확정값 검사, 제출본, 기한 계산은 업무 메서드로 표현한다. 인증 주체·기관·배정·revision과 여러 애그리거트의 트랜잭션은 서비스에서 조율한다. 서버가 최종 판단한다.
5. **LLM 경계를 공통 어댑터로 유지한다.** Spring AI 2.0.0 BOM의 `spring-ai-client-chat`, `spring-ai-pgvector-store`를 고정한다. `LlmGateway` 뒤에 Spring AI `ChatClient`/`ChatModel`을 연결하고 기존 `BoundedModelHttpClient`의 엔드포인트 허용 목록·공개 DNS 검사·리다이렉트 거부·시간/응답 크기 제한을 재사용한다. 특정 공급자 모델 구현체가 업무 domain에 침투하지 않는다.
6. **모델 구성은 데이터, 키는 참조로 다룬다.** 공급자·모델·허용된 엔드포인트를 DB에서 선택하고 키 원문은 환경변수에 둔다. 키 없는 기본 EXAMPLE 추출은 실제 LLM 호출로 표시하지 않는다. 신규 사업 건 분석은 대상 revision·근거·미확정 상태와 연결한다.
7. **디자인 원본을 고치지 않는다.** 이번 참고 커밋은 출처 기록과 PR에 남긴다. 업무 의미는 FUNCTIONAL_SPEC, 시각 규칙은 design.md, 개별 화면 모양은 구현 직전 prototype-soo 최신본을 따른다. design.md 갱신은 디자이너의 후속 작업이다.

## 구현 가정과 후속 인수

신규 API의 이름·DTO·질문 키와 [glossary.md](../glossary.md)는 이번 시작점의 구현 계약이다. 규칙 문서의 새 업무 결정을 추가한 것으로 해석하지 않는다. 정책 게시본·기관별 달력·담당자 후보군의 현재 축소 범위는 코드와 API 계약에 명시하고 후속 담당자가 인수한다.

기존 procedure의 초안→협의→제출→접수와 가변 검토 순서는 신규 4단계 업무의 기준이 아니다. 신규 상태를 기존 경로에서 조작하거나 기존 모델의 ID를 새 자원에 전달하지 않는다. 기존 분석·설정 자산을 이관할 때 계약을 명시하고 한 업무 규칙을 두 모델에서 병행 운영하지 않도록 정리한다.

F-15 정책 수명주기, F-16 지표, F-17 알림 실행 기능은 **설계 완료·구현 예정**으로 남긴다. 기본 스키마가 존재하는 경우에도 기능 완료로 표시하지 않는다. P2는 필수 경로 리허설 통과 후에만 착수한다.

## 검증과 한계

JDK 25 빌드·도메인/통합 검사와 프런트엔드 검사·빌드는 이번 변경 대상으로 새로 실행한다. 실제 결과는 [verification-starter.md](../verification-starter.md)에 기록한다. 2026-11-06의 Java 21·이전 업무 검사 결과는 이번 통과 증거로 재사용하지 않는다.

검증 환경에 Docker가 없으면 외부 PostgreSQL 17 테스트와 Docker/Testcontainers 미실행을 구분한다. Compose는 `pgvector/pgvector:0.8.7-pg17-bookworm`과 `scripts/db/02-pgvector.sql`로 새 볼륨의 vector 확장을 준비한다. 기존 볼륨에는 초기화 스크립트가 다시 실행되지 않으므로 설치 상태를 별도로 확인한다. 의존성 고정·컴파일·EXAMPLE 동작만으로 실제 외부 LLM 2종 구동, RAG 색인·검색, Docker 전체 구동을 입증하지 않는다. 해당 항목은 실제 결과가 있을 때만 완료로 기록한다.

이번 결정은 main 직접 push나 자동 병합 권한을 만들지 않는다. 기능 브랜치·PR·작성자 외 사람의 승인·Squash merge 절차를 따른다.
