브라우저 QA: 클라우드 Chrome, 데스크톱 뷰포트 1348px. 실제 모바일 기기 대신 같은 앱을 320·360·768px iframe으로 표시해 배치를 검사했다. 320px와 768px에서 문서 전체 가로 넘침 없음(스크롤바 제외 콘텐츠 너비 305·753px). 200%는 앱의 글자 크기 설정을 사용했으며 브라우저 400% 확대 검사와 다르다.

- 네 역할 전환과 시작 화면, 신청자 범위 2건 표시 확인.
- 업무 요약의 보완 요청 카드 → 요청함 2건, 필터 적용 확인.
- 신청자 문서함에서 “차세대” 검색 → 1건, 제출본 조건 → 0건·초기화 안내 확인.
- 미리보기에서 신청번호·미확정 정보·파일명·TXT 크기 확인.
- 키보드 Enter로 모달 열기 → Escape로 닫기 → 원래 미리보기 버튼으로 초점 복귀 확인.
- 새 신청에서 빈 필수값으로 다음 단계 진행 불가, 입력 요소 초점 확인.
- 320px에서 메뉴를 열어 문서함으로 이동, 검색 폼이 한 열로 배치되는 것 확인.
- 앱 200% 글자 크기에서 페이지 가로 넘침 없음 확인. 모든 개별 컴포넌트의 확대 가독성 인증을 뜻하지 않음.
- 기관 관리자 설정 진입, 게시본/초안·질문 목록·설정 제약 안내 확인.

## 미검증·후속 범위

- 이 환경에 Docker 실행 파일이 없어 실제 Compose 기동·컨테이너 smoke 검사를 다시 실행하지 않았다. 기존 Docker 구성은 변경하지 않았다.
- 백엔드 소스 변경 없음. 이번 작업에서 Maven 검사는 재실행하지 않았다.
- 다운로드 콘텐츠·BOM을 포함한 크기는 동일 문자열에서 생성한다. 실제 브라우저 다운로드 파일의 바이트 비교는 미실행.
- 스크린리더, 400% 브라우저 확대, 모든 상태의 색상 대비, 실제 모바일 브라우저 전체 검사는 미실행.
- 실제 인증·기관 권한·AI·기관 전송·DB 저장은 없다. 시연 상태는 sessionStorage에만 저장된다.
- 조건부 질문 평가·모든 응답 형식·단계별 필수 조건 엔진, 기관 양식/PDF/DOCX 생성, 후속 처리 결과 연동은 미구현이다.
- 전체 KRDS 준수 또는 접근성 인증으로 해석하지 않는다. 상세 기존 제한은 README.md와 validation-v3.md를 함께 확인한다.
